Text files under cascade/ are the hub's files at the commits in SOURCE, byte for byte, except the files listed at the
end and the files written for this release (SOURCE names them); every file or directory name that held an Alpine job id
holds that job's label instead. In the listed files internal names were replaced as bb72/SANITIZE.txt describes, each as
an exact replacement with the same text everywhere it occurs, and some passages were cut or reworded as described below.
No number, rule or result changed.
- Cluster jobs. Each Alpine job id became a label, CJ01 to CJ74, numbered in the order of the ids, which is the order in
  which the jobs were submitted; text, file names and directory names use the same label (for example the multi-shot
  engine's jobs CJ55 to CJ59 and their report CJ65, the exploratory look CJ66, D1's read jobs CJ71 and CJ72). The
  curve sets' jobs became CC01 to CC16 in the same way, and a range of their ids a range of labels (CC07-CC10).
- The account and paths. The cluster account became <user> and its scratch directory <cluster-scratch>, in every form
  the files used (compute-node and relative forms included). Work directories on the Linux workstation and on the Mac
  mini became ~/work/... (~/work/repo.git, ~/work/relay, ~/work/cascade_..., ~/work/h100t_state, ~/work/h100b_state).
  The H100 pods' own paths (/opt/...) and Alpine's node names stay, as in bb72/.
- Hosts. The Linux workstation's ssh host name became x86-host, and in prose "the Linux workstation"; the Windows
  workstation that trained C6' is "the Windows workstation". The Mac mini's host name became m4-host. The H100 pods'
  container host names became gpu-pod, their GPU UUIDs GPU-<uuid>, and the serial number and PDI in the nvidia-smi
  records <serial> and <pdi>.
- Names. The coordinating role became "the study lead", "the user" became "the authors", and run names and
  bylines were removed or replaced by their role (the training stage, the noise-model fit, the curve sets, the first
  and second H100 pod, the H100 session, milestone 1 or 2). Names that are identifiers stay as they are: the variables
  W2, W3, W4 and W6 in the code (pc_common.W4 is phase C's run directory, curves.W2 the curve sets'), the environment
  variables W2_DIR and W2_ROWS, the curve sets' splits w2test and w2cal and job names w2_*, the directory names
  cascade_w1 to cascade_w5, cascade_h100b, fix/, fix2/, fix3/ and w2fix/, and the job names w4f2_smoke_rtx and
  w4f2_smoke_h200. Mentions of the gate reviews and of their finding numbers stay, as in r17/; the review texts are
  not part of this release.
- Passages cut. Operational instructions, the H100 pods' pull loop and spend watchdog, forecasts, deadlines,
  rental prices, plans for later work and the lever ranking and optimization plan of batchopt/PROFILE.md (sections 8
  and 9; batchopt/M2.md states the targets it measured against) were cut. Each cut leaves a note in square brackets;
  shorter removals inside a paragraph leave none. References in the code and in two M2 summaries to the cut sections
  now point to M2.md.
- Training code. The training program is not part of this release. bb/cascade_eval.py imports p_block_to_pl and
  wilson from bb/cascade_stats.py, a verbatim copy of the two functions of bb/cascade_train.py at 64b2e25d, instead of
  from bb/cascade_train.py; bb/cascade_data.py lost train_seed, the training streams (the Stim stream, dem_dense and the
  DEM sampler) and the sampler benchmark, and its command line keeps check and env. cascade_eval's --bn-recal needs
  bb/cascade_optim.py (training code) and does not run here; no read of the comparison used it.
- Weights. weights/ holds inference checkpoints made from the checkpoints the comparison read
  (repro/strip_checkpoint.py): Cascade's EMA weights with the architecture fields of its configuration, and the
  ConvLines networks' weights with their full configuration. Every tensor is byte for byte the original's. Each file
  records the original's sha256 as source_sha256; that is the sha256 that the locks, the reads' signatures and the
  timing rows give for the network, and the paths they give (<cluster-scratch>/cascade_w3/ckpt/<name>/final_ema.pt,
  cascade_w4/ckpt/C6_dfm/ for C6') are the originals'. The training metadata in the originals (arguments, curriculum,
  logs, hosts, job ids) is not part of this release.
Hashes recorded before these replacements keep their values and refer to the hub's files:
- phase_c/out/locked_uniform.json and locked_depspam_fm.json differ from the hub's in paths, so their sha256 is not the
  locked_sha256 that the confirmation, the check, the timing rows, the report and the multi-shot rows record. The same
  holds for D1's lock (phase_d/d1_locked_depspam_fm.json, paths and job labels): d1_result.json's lock_sha256 and the
  D1 rows' locked_sha256 refer to the hub's file. The check files of the first lock (phase_c/out/lock_1e8d1c6d/)
  record that lock's sha256, and the first lock itself is not part of this release. Steps that hash a lock
  (pc_route.py, pc_report.py --locked, d1_confirm.py) get other hashes from these copies than the records hold, and
  pc_report.py refuses them; repro/recompute_numbers.py takes the recorded sha256 from the records instead.
- The reads' signatures, explore_deep.json's inputs and the D1 freeze record give the sha256 of files as they were on
  the cluster (checkpoints, locks, code trees); the checkpoints' are the released files' source_sha256.
Byte for byte the hub's, so their recorded sha256 can be checked here: phase_c/out/speed_components.json (the locks'
speed_sha256), phase_c/out/npz_sha256.txt and phase_d/out/npz_sha256.txt (the per-shot files on the cluster), and
every file not listed below.
